# Image Scene Inventor

以提示词仓库里的模板为唯一风格来源。不要用通俗印象替代模板，也不要引入预设风格表、场景池或随机脚本。

## 仓库位置

默认 `~/apps/image-prompt`。先确认它存在；不存在就询问用户仓库位置。

## 铁律

1. **先选模板，再读全文，再写。** 必须读完主模板，包括禁止清单。
2. **目录是分类，不等于单一风格。** 同一目录可以同时包含场景模板、角色设定、昼夜变体、世界观设定和参数模板。不要默认把目录内所有文件混成一套风格。
3. **模板 DNA 不只包括摄影参数。** 角色身份、世界观、标志性造型、媒介、空间关系、尺度参照、材质逻辑、界面结构和情绪命题都可能是风格的一部分。
4. **具体元素可以是锁死项。** 孙悟空、金箍棒、体素 HUD、生物机械铠甲等如果承担识别或结构作用，就必须保留；不要为了“创新”机械地清空模板物件。
5. **用户说的话是最高约束。** 主体、题材、画风、情绪、用途、画幅和改动幅度都按用户要求执行。
6. 找不到对应目录或模板时，不要硬套最相近的分类。

## 选择主模板

1. 先列目录和文件名，并读取仓库 README 的导航说明；快速比较候选模板的媒介、画幅、主体和用途，判断分类内部是否存在不同路线。
2. 用户点名文件、示例图或明确主体时，选择对应文件为**主模板**。
3. 用户只说分类时，根据他的主体和用途选择最匹配的一份主模板。分类名只是候选范围：例如同一分类中可能同时存在写实摄影与数字插画、完整场景与角色设定。不同候选会导致明显不同的世界、媒介或构图时，先列出简短路线并推荐一条；用户没有指定时可按推荐路线继续，不要混合候选。
4. 只在以下情况读取辅助模板：
   - 与主模板明确属于同一系列，例如同一角色的昼夜版；
   - 主模板明确要求拼入某个角色设定块或世界观设定块；
   - 用户明确要求融合两份模板。
5. 辅助模板只补充兼容的部分；发生冲突时，以用户要求和主模板为准。

## 判断模板类型

读完后先判断主模板属于哪一类，再决定如何派生：

- **完整场景模板**：保留核心视觉关系，在同一世界里改变事件、时刻、动作或局部地点。
- **世界观 / 系列设定**：保留建筑语言、角色规则、尺度逻辑和允许的动态，重新组合一张完整场景。
- **角色 / 道具设定块**：锁死辨识结构，把它拼入一个兼容场景；除非用户明确要求，不要重造角色。
- **参数化模板**：优先填写或变更模板已经暴露的参数，保留界面、格式和固定结构。
- **短风格 / 情绪模板**：忠实继承其中真实存在的媒介、笔触、色彩、光线和情绪，不要凭空补出焦段、百分比或复杂世界观。

## 提取模板 DNA

把模板内容分成三层。分类依据是它在成品中的**功能**，不是它是不是具体名词。

### 锁死项

默认保留：

- 媒介与成像方式：真人实拍、插画、体素游戏截图、手机快照等；
- 世界与类型身份：东方蒸汽朋克水城、东方神话废墟、都市巨物灾难等；
- 用户点名的角色、物种、道具及标志性造型；
- 核心构图语法与视觉关系：前景压框、巨物与尺度参照、人物与引导线、第一人称 HUD 等；
- 材质和物理逻辑；
- 核心情绪命题；
- 仍然适用于新场景的禁止清单。

### 可控变量

按用户要求一次改变一个或少数几个：

- 故事发生的前一刻、当下或后一刻；
- 动作、事件、天气、时刻和季节；
- 同一世界中的局部地点；
- 摄影距离、机位或焦段，但不得破坏模板赖以成立的空间关系；
- 角色状态和环境动态。

### 可替换细节

可以重新设计不承担身份或结构作用的背景物、装饰物、次要人物、偶然道具和表面细节。

不要使用“成品与模板不能有任何共同物件”作为创新标准。正确标准是：**保留模板身份，产生新的画面事件，不照抄原模板的完整元素组合和段落。**

## 两种派生模式

### 同世界续拍（默认）

用户说“还能拍什么”“基于这套再想”“换个场景”或没有明确要求换题材时，采用此模式：

1. 保留锁死项和标志性具体元素。
2. 选择一个清楚的新事件或新状态。
3. 改变足以形成新画面的变量，同时维持角色、世界与视觉语法连续。
4. 系列图只改变约定变量，共享设定逐字一致。

### 跨题材风格迁移

只有用户明确提出新主体、新题材或“用这套画风拍另一个东西”时采用：

1. 用户的新题材覆盖原模板的题材身份。
2. 保留媒介、材质、光色、构图语法、尺度逻辑和描述密度。
3. 按视觉功能做**角色对角色映射**，不要只删物件。例如：
   - 原来的城市是尺度参照，就为新主体设计等效尺度参照；
   - 原来的金箍棒承担前景对角引导线，就用新题材中合理的长形元素承担同一功能；
   - 原来的 HUD 定义游戏截图格式，就保留 HUD，只替换模板允许变化的内容。
4. 删除只属于原题材且无法映射的禁止项；补充新题材确实需要防止的失败项。

## 写 Prompt

1. 沿用模板的语言习惯、章节结构和实际描述精度，但不要复制整段句子。
2. 模板有精确数字时，保留仍有作用的数字；改变构图后重新计算对应关系。模板没有数字时，不要为了显得专业而编造数字。
3. 正向部分只使用肯定描述。把模板中“不是 A，而是 B”的有效意图改写为明确的正向 B，并将 A 整理进 Negative Prompt。成品正文不得残留“不是”“不要”“没有”“禁止”“避免”或对应英文否定句。
4. Negative Prompt 只保留与当前成品相关的条目，不要无脑复制，也不要违反主模板的禁止逻辑。
5. 每份 Prompt 前用一句话说清这次拍的是什么。直接给成品，不留占位符，不夹过程解释。

## 输出语言

每份 Prompt 输出两个互相独立、可直接粘贴的版本：

- **中文版**：正文与 Negative Prompt 使用中文。英文技术术语译成中文；胶片、器材、品牌、作品名、专有名词和用户要求画面中原样出现的文字可以保留原文。
- **英文版**：正文与 Negative Prompt 使用英文，不出现中文；用户明确要求画面中出现的中文文字除外。
- 两版的主体、数字、构图、材质、光线和 Negative 条目逐项对应。

## 用户完全没想法时

列出仓库中的实际分类，并用模板内容概括每类的视觉命题。挑选一个最能形成新事件的主模板，默认做同世界续拍；也可以建议三联“之前 / 当中 / 之后”、只换单一变量的对照组或同世界九宫格。

## 自检

- 主模板是否明确？有没有把整个目录误当成同一套风格？
- 是否判断了模板类型，并按该类型派生？
- 角色、世界、标志物、空间关系或格式中，哪些是锁死项？是否误删？
- 新画面是否有真正的新事件，而不是原模板换几个名词？
- 跨题材时是否完成了视觉功能映射，而不是清空具体元素？
- 是否只使用模板实际提供的精度，没有凭空发明参数？
- Negative Prompt 是否仍适用于当前场景？
- 正向正文是否清除了所有否定句，并把必要排除项移入 Negative Prompt？
- 用户明确要求是否全部落实？
- 两种语言是否独立完整、逐项对应？
