# Image Scene Inventor

提示词仓库里的模板是唯一风格来源。不要用通俗印象替代模板，也不要引入预设风格表、场景池或随机脚本。

## 仓库位置

默认 `~/apps/image-prompt`。先确认它存在；不存在就询问用户仓库位置。

## 铁律

1. **先判模板类型，再决定拿什么、换什么。** 派生方法由主模板本身的形态决定，不由目录名决定。环境规格按环境派生，角色规格按角色派生。
2. **先选主模板，再读全文，再写。** 必须读完主模板，包括禁止清单。
3. **模板是视觉规格，不是场景清单。** 它可以是摄影规格、插画规格、角色设计规格、世界观设定集或游戏截图格式；从中提取风格和技术，不默认继承具体题材。
4. **用户说的话是硬约束。** 主体、题材、人物、画风、情绪、用途、画幅和保留项，说了就照做。
5. **输出是规格，不是模板的复印件，也不是模板的换皮。** 模板可能写成叙事体；成品一律是分节、可测量、正向肯定的专业 Prompt。逐行对位替换名词等于复印，见「反换皮检查」。
6. 找不到对应目录或模板时，不要硬套最相近的分类。

## 选择主模板

1. 列出目录和文件名，必要时读取 README 导航。
2. 用户点名文件、示例图或明确主体时，选择对应文件为主模板。
3. 用户只说分类时，比较候选模板的媒介、画幅、主体类型和视觉路线，选择最匹配的一份。候选差异明显时，列出简短路线并推荐一份；不要把整个目录混在一起。
4. 只有用户明确要求融合，才读取并组合多份模板。设定集与同目录单张模板配套阅读是设定集的正常用法，不算混读。

## 判定模板类型

先看格式，命中任一条就走对应分支：

- 含 `{argument name="..." default="..."}` → **参数化模板型**
- 分节罗列多组可选设定或可选动态、明说供成组出图 → **设定集型**
- 通篇是对模型说话的指令而非画面描述 → **元指令型**

否则按篇幅分布判主体：

- 大部分篇幅写地点、空间层次、建筑、天象、光线 → **环境主导型**
- 大部分篇幅写角色或生物的逐部位设计、材质工艺、解剖结构 → **角色主导型**
- 两侧都有完整章节 → **双主体型**

仓库现状参照（以文件实际内容为准，新增文件同法判定）：

- 环境主导：`治愈/夏日海边`、`治愈/滑板治愈`、`梦幻空灵/童话`、`梦幻空灵/无人区-童话`、`梦幻空灵/prompt-one`、`武侠/蒸汽朋克`、`武侠/蒸汽朋克-水城`、`武侠/赛博朋克`、`宏大风格/宫阙图`、`宫崎骏画风/意大利旅游`
- 角色主导：`武侠/将军`、`武侠/骑士-正面`、`怪兽/近距离大鸟`
- 双主体：`武侠/机甲`、`武侠/机甲-白天`、`武侠/机甲-夜晚`、`西游记/悟空`
- 设定集：`宏大风格/prompt-two`
- 参数化：`游戏/我的世界`
- 元指令：`日常 emo/prompt-one`

## 环境主导型

**拿**：媒介与画质；镜头语言（焦段、机位高度、俯仰、视角、主体比例、景深、运动模糊、星芒眩光）；空间层次的组织方法（前景压框、引导线、负空间、前中远递进）；尺度对比手法；光线与色彩关系；材质与物理逻辑；描述精度；Negative 的排除逻辑；**主体的存在方式与真实性锚点**。

最后一项容易漏。模板规定人或载体「平凡、真实、非幻想化」时，这是风格机制而不是题材：`梦幻空灵/童话` 要求人物是普通现代女孩、明写不要古装、披风、铠甲和幻想服装；`梦幻空灵/无人区-童话` 要求先让人相信这是一艘真实存在的普通渡轮，然后才发现天空不对劲。奇观之所以成立，靠的就是主体的平凡。换掉具体身份或载体，但保留这条约束和它在画面中的占比、角色定位。

**换**：地点与地貌；建筑与设施；人物身份、物种与服装；植物、载具与道具；天象、幻想奇观与具体天气事件；原模板的故事时刻；只为原场景服务的空间排列。

**改动下限**：

1. 成品与主模板不共享具体地点、建筑、载具、道具或核心奇观。
2. 只换天气、时刻、动作或观察方向，不算新场景。
3. 不能沿用原模板的完整场景骨架后只增加一个事件。
4. 原物件承担引导线、尺度参照、前景压框或「担保这是真实世界」的作用时，为新题材重新发明承担同一功能的元素。
5. 换掉全部物件之后，还要过「反换皮检查」：结构同构一样是复印件。

例如使用 `梦幻空灵/无人区-童话.md` 时，可以继承现实旅行摄影、普通现实环境与不可能奇观的反差、广角沉浸感、巨大天空、冷暖关系和精确描述；默认不能继续使用渡轮、甲板、海面、航迹、星河漩涡和粉色月亮。

## 角色主导型

主体是角色本身。**不要把"人物身份与服装"整体判为可丢弃**——那是环境型的规则，套到这里会把模板清空。服装的**工艺与结构逻辑**属于风格层，服装的**主题与母题**属于题材层。

**拿**：

- 立绘格式：正面 / 侧后 / 仰视，半身或全身，机位、视角、人物在画面中的比例、背景处理方式（纯色背景，或环境只作尺度参照）；
- 设计配方：模板融合了哪几套形制传统（东方武将甲 + 欧洲板甲 + 外骨骼 + 生物机械），这个配方本身是风格；
- 真实性锚点：真人五官、真实皮肤纹理、真实人体比例，以及"不是机器人 / 不是驾驶员 / 不是全覆盖盔甲"这类身份边界；
- 材质与工艺：金属种类、划痕、磨损、油污、暴露的机械结构，鳞片、角质、羽毛、皮肤褶皱的物理逻辑；
- 逐部位的描述顺序与粒度：头盔 → 肩甲 → 胸甲 → 臂甲 → 裙甲 → 腿甲 → 武器 → 战损；
- 生物类另拿：解剖可信度要求、"一眼看出是什么"的轮廓判据、尺度参照方法、镜头裁切规则（如禁止完整轮廓、主体占画面比例、张口角度这类硬指标的写法）；
- Negative 的形制排除逻辑。

**换**：具体身份、物种、性别与年龄取向；装备的主题与用途（战阵 → 深海、狩猎、仪典、工程）；造型母题（羽翼状肩甲、鳞片胸甲、长马尾、破损围巾等具体母题）；武器与随身道具；配色与纹样；背景环境（模板写了的话）。

**改动下限**：

1. 不共享同一角色 = 不同时沿用原物种、原装备主题和原廓形母题。
2. 只换配色、只换武器或只改姿势，不算新角色。
3. 生物类不沿用原型物种，换到别的解剖门类，但保留同一套"真实活体组织"的材质要求与尺度手法。
4. Negative 的形制排除按新角色重写：原模板禁止日式兜的锅錣是为了守住欧式全覆头盔轮廓；新角色要写它自己需要挡掉的错误形制，不要照抄这一条。

## 双主体型

角色和环境的章节都完整时，两侧都要重想，各自适用上面对应的改动下限，不能只换一侧。用户点名只换一侧时，另一侧进入保留模式。

## 设定集型

它是一组图共用的规格，不是单张提示词。默认沿用它的分节体系、规格粒度和"每张只用一种主导动态"的规矩，重新发明各节的具体内容，成组输出。用户要单张时，从设定集派生一张，并说明取了哪一节动态。

## 参数化模板型

`{argument name="..." default="..."}` 语法保留。界面、HUD、构图骨架属于技术规格，不是题材，一并保留。派生 = 重新设计每个变量的 `default` 值，必要时增删变量。成品仍是可直接投喂的模板，每个变量都带可直接出图的 `default`。

## 元指令型

它是对模型说话的指令，不是画面描述。保留这种说话方式、"不完美"的质感要求和它的语言。不要把它改写成分节的长规格。

## 极短模板的补充规则

模板本身没有焦段、数字或 Negative 时，不要凭空补出来，按模板实际粒度写。确需补充时只补与模板媒介相容的项：插画类媒介补笔触、印刷质感、色彩关系，**不要给插画类媒介补摄影参数**。

## 例外与模式

1. **用户明确要求保留**：说出"保留孙悟空 / 金箍棒 / 渡轮"、"沿用这个世界"、"拍前一刻 / 后一刻"、"只改天气 / 动作 / 时间"、"做同一角色或同一世界的系列图"时，锁死用户点名的内容，其余部分仍按模板规格重新设计。不要自行把"还能拍什么""再想一个""基于这套"解释成同世界续拍。
2. **系列图 / 单变量**：主模板本身就是系列范例（`武侠/机甲-白天` 与 `机甲-夜晚`），或用户要成组产出时，"共用设定 + 只改一个变量"是合法输出，此时不适用改动下限。
3. **IP 分类**：分类由具体角色定义时（西游记 = 孙悟空），该角色属于风格层，默认保留，按主体类型的其余规则重想场景与时刻。

## 反换皮检查

换掉全部具体物件，仍然可能只是换皮。判据是**结构是否同构**：把成品与主模板逐句并排，如果每一句都能在对方找到功能相同、位置相同的对应句，那就是复印件，名词换了多少都不算数。

典型失败样例（以 `治愈/夏日海边` 为主模板）：铁路→乡道、电车→卡车、住宅→农舍、海湾→葵田、船只→收割机、积雨云→云墙、海平线百分比→地平线百分比，二十行一一对位，成品还是同一张图。

成品必须在下列结构位中**至少改掉两项**，且改法要有画面上的理由，不是随机打乱：

- **前景主体的存在方式**：横向高速掠过 / 静止压框 / 向镜头纵深逼近 / 取消前景主体，改由地形或天象承担压框。
- **空间层次的数量与递进方式**：前中远三层 / 两层加大面积负空间 / 四层逐级抬升 / 单一连续纵深。
- **主导动态的成因与方向**：载具运动 / 气象运动 / 水体运动 / 群体生物运动 / 光线自身移动。
- **尺度参照物的位置**：远景极小参照 / 前景巨大参照 / 参照物紧贴主体旁边。
- **视线引导路径**：由下向上 / 沿一条线由近及远 / 由外向内向中心收拢 / 无引导线，靠明暗块面分区。

数值同理。主体占画幅比例、地平线高度百分比、机位高度、俯仰角必须按新构图重算，并说得出为什么是这个值；把 `55%–65%`、`45%–48%`、`15–25 米` 微调几个数字后照搬，等于没改构图。焦段与画幅属于媒介规格，可以沿用。

## 视觉机制移植检查

模板里每一个视觉效果都有物理成因。移植前先说清成因，再验证新载体能不能产生它。

1. **指认成因。** 「海面成千上万个密集银白闪光点」＝水面镜面反射 + 微波纹随机取向；「云顶银色轮廓光」＝逆光下水滴的边缘散射；「金属星芒」＝光圈叶片衍射 + 镜面高光。
2. **验证新载体。** 新题材里占据这个位置的物体是否具备同一物理性质：镜面反射、透射、折射、金属高光、自发光。植物绒毛是漫射透光，给不出点状锐利高光；哑光夯土墙给不出星芒。
3. **不具备就换机制，不要硬安。** 需要「整片密集闪耀」时，在新场景里找真正能产生它的载体（水面、湿地、大棚膜、金属屋顶、玻璃、渠道水面），或者放弃这个效果，改由别的机制承担同等画面分量。宁可换掉效果，也不要写出模型画不出来的指令。

同时做画面自洽检查，任一条冲突就重写那一句：

- **朝向与可见面**：规定了背对镜头，就不能同时规定正面细节；规定了逆光，正面材质细节不可见，只剩轮廓、透光与边缘散射。
- **光源方向**：所有阴影、高光、星芒、透光必须来自同一个已声明的光源位置。
- **物候与时序**：季节、农时、花期、潮汐、日高度角必须能同时成立（麦收与向日葵盛花不在同一周）。
- **运动与锐度**：同一物体不能既运动模糊又「清晰可数」；声明模糊的对象和声明锐利的对象必须互不重叠。

## 篇幅与信息密度

长不等于专业。硬指令堆到注意力稀释以后，模型画出来的一定不是写的那张。

- **成品正文行数不超过主模板的 1.2 倍。** 主模板 20 行，成品写到 50 行就是失控，删回 24 行以内。
- **画面中同时存在的独立视觉元素组不超过 7 组**（前景主体 / 前景设施层 / 中景主体 / 侧翼 / 远景 / 天空 / 光效）。超了就整组删掉，而不是压缩成一个从句。
- **一行只规定一件事。** 一行里塞进三个以上并列名词清单时，模型只会挑一两个画；把清单删到三项以内的代表物。
- **同一效果只规定一次。** 星芒、闪光、高光、眩光分散在五处重复强调等于没有重点；集中在一节写清两层高光的尺寸与密度差异。
- **不写元话语。** 「成千上万个闪光点必须由花盘承担」「真正的压迫感来自……」是创作说明，不是画面规定；直接写那个物体的形态与指标。
- 写不动时停手。想不出还能加什么，不是密度不够，是骨架不成立，回去重想结构。

## 写 Prompt

**成品一律是专业规格式 Prompt，与主模板的行文腔调无关。**模板是素材，不是要抄的成品。

1. **版式照搬，腔调不照搬。** 仓库模板有统一版式，成品必须长得像同一个仓库里的文件：开篇一句锁死画幅与媒介；关键规格用 `**加粗**` 打出来；**一句一行，句间空行**；大块之间用 `---` 分隔；单独的设计难点用 `###` 单起一节（如 `### 如意金箍棒必须成为画面中第二重要的视觉元素`）；结尾用一句「最终必须像……」收束。不要把它压成【】标题下的密排长段落。
2. 沿用模板的**分节体系与描述精度**，不沿用它的行文腔调，不复制整段句子。仓库里多份模板是叙事体——`西游记/悟空`、`武侠/机甲` 三版、`武侠/骑士-正面` 通篇「不是 X 而是 Y」的对照句，外加「王已经坐下了」「真正的压迫感来自……」这类情绪判词。那是写给人看的创作说明，不是给模型的画面规定。取它规定的**内容**，换成规格写法输出。
3. **情绪判词与对照句必须落成可执行项**，不能原样留在成品里：
   - 情绪与状态（「他在等它来」「王已经坐下了」）→ 面部肌肉松紧、眉骨与下颌状态、视线方向与落点、呼吸、重心落在哪条腿、身体哪一部分保持静止。
   - 「不是 X 而是 Y」→ 正文只写 Y 的具体形态，X 作为词条进 Negative。
   - 「真正的气势 / 压迫感来自……」→ 换成产生该效果的具体机制：透视层级、占画幅比例、动静对比、尺度参照物。
   - 「整座山都在被风撕扯，只有他站得稳」这类整体感受 → 哪些元素位移、朝哪个方向、位移量多大、是否带运动模糊、哪些元素保持锐利静止。
4. 每份成品必须齐备：画幅与媒介一句话、分节标题、逐节的肯定式画面规定、单一主导动态、色彩与胶片质感、关键词块、Negative Prompt。
5. 模板有精确数字时，按新题材重新建立同等精度的数字关系；不要把只适用于原场景的数值机械照搬。
6. 主模板是摄影类长规格但漏写了某个构图参数时（机位高度、焦段、俯仰角、主体占画幅比例、主导动态方向），补齐可测量值——这是把规格补完整，不受「极短模板的补充规则」限制；该规则只约束极短模板与插画类媒介。
7. 正向部分只使用肯定描述。即使主模板正文大量使用加粗否定句，成品也把这些排除项下沉到 Negative Prompt。
8. Negative Prompt 根据新题材重写，只继承主模板的排除逻辑，不复制已经失效的具体条目；正文里被下沉的每个否定项，这里都要有对应词条。
9. 每份 Prompt 前用一句话说清这次拍的是什么。直接给成品，不留占位符，不夹过程解释。

**成品骨架**（摄影类长规格照此排布，其余类型按各自分支的格式）：

```text
一句话说明这次拍的是什么。

**9:16 竖向构图**，媒介、画质与整体路线一句锁死。

---

**镜头与机位**：焦段、机位高度、俯角、主体占画幅比例。

**前景**：主体一行，设施层一行。

**中景**：主体及其与前景的空间关系。

**远景与天空**：层次、尺度参照、光源位置。

### 单独的设计难点

把最难画的那一件事单起一节，写清它的物理成因与可测量指标。

---

**主导动态**：唯一一种运动，方向与成因；谁带运动模糊，谁保持锐利。

**色彩与胶片质感**：色彩关系与胶片参照。

**关键词块**：术语，逗号分隔。

**Negative Prompt**：术语，逗号分隔。

最终必须像……（一句收束）
```

**例外**：元指令型与参数化模板型按各自分支的格式规则输出，第 1、2、4 条与本骨架不适用——它们的原格式本身就是规格。

## 输出语言

默认每份 Prompt 输出两个独立、可直接粘贴的版本：

- **中文版**：正文与 Negative Prompt 使用中文。胶片、器材、品牌、作品名、专有名词和用户要求原样出现的画面文字可以保留原文。
- **英文版**：正文与 Negative Prompt 使用英文；用户明确要求出现的中文画面文字除外。
- 两版的主体、数字、构图、材质、光线和 Negative 条目逐项对应。

主模板是英文原生时（`日常 emo/prompt-one`、`游戏/我的世界`），以英文版为主版并保持它原有的措辞习惯。元指令型和参数化模板型默认只给模板原语言的一版，用户要双语时再补。

## 用户完全没想法时

列出仓库中的实际分类、其中不同模板路线和它们的主体类型，推荐一份主模板，然后按该类型的默认规则直接发明新题材。三联、单变量对照组或同世界九宫格只作为建议；用户选择后才启用。

## 自检

交付前逐条过一遍。任何一条不通过就回去重写，不要把问题连同成品一起交出去。

- 是否只选择了一份明确的主模板，没有混读整个目录？
- 是否先判定了模板类型，并执行了该类型的派生规则？
- 环境型：拿的是媒介、镜头、空间组织、尺度手法、光色、材质、精度和 Negative 逻辑吗？是否错误保留了原地点、建筑、载具、道具或核心奇观？
- 环境型：模板要求主体平凡、真实、非幻想化时，这条约束保住了吗，还是连人物的存在方式一起换掉了？
- 角色型：拿的是立绘格式、设计配方、真实性锚点、材质工艺、逐部位粒度和形制排除逻辑吗？是否把角色设计当成可丢弃的题材层删空了？
- 角色型：新角色是否同时换掉了物种、装备主题和廓形母题，而不是只换配色或武器？
- 双主体型：两侧是否都换了？
- **反换皮**：成品与主模板逐句并排后，是不是每一句都能一一对位？结构位上至少改掉两项了吗？
- **反换皮**：主体占画幅比例、地平线高度、机位高度、俯仰角是按新构图重算的，还是把模板数字微调了几位？
- **机制移植**：正文里每个视觉效果，新载体在物理上产生得出来吗？有没有把镜面反射类效果安到漫反射物体上？
- **自洽**：朝向与可见面、光源方向、物候时序、运动与锐度，四项有没有互相打架？
- **密度**：行数是否在主模板 1.2 倍以内？独立视觉元素组是否不超过 7 组？有没有同一效果重复规定？
- **元话语**：「必须由 X 承担」「真正的气势来自……」这类写给人看的话，有没有留在成品里？
- 设定集 / 参数化 / 元指令：是否保留了它们各自的格式，没有被改写成单场景长规格？
- 极短模板：是否凭空补了模板没有的精度，或给插画媒介写了摄影参数？
- 用户没有明确要求时，是否擅自做了同世界续拍？
- 成品版式是否和主模板一致：开篇画幅句、加粗关键规格、一句一行、空行分段、`---` 分块、结尾收束句？
- 成品是否是规格式写法？模板的叙事腔调、「不是 X 而是 Y」对照句和情绪判词有没有被原样搬进成品？
- 模板里的情绪要求是否落成了面部、视线、重心、动静对比这类可执行项？
- 构图参数是否齐全：画幅、媒介、焦段、机位高度、俯仰角、主体占画幅比例、单一主导动态方向？
- 正向正文是否清除了否定句，排除项是否都下沉到 Negative？
- 用户明确要求是否全部落实？
- 输出语言是否符合主模板的原生语言规则，两版是否逐项对应？
