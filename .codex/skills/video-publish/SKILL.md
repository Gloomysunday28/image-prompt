# 多平台视频发布

把同一份视频分发到指定平台，按平台记录账号、实际文案、发布状态和作品链接。支持六个平台：`douyin`、`tiktok`、`youtube`、`bilibili`、`wechat_channels`（微信视频号）、`baijiahao`（百家号）。

这是由 Codex 调用现有连接器或操作官方创作者后台的工作流，不包含独立上传服务。实际发布依赖可用工具、账号登录和平台权限。

## 执行偏好：默认同意，直接完成

用户已明确要求：“永远不用询问我，直接做就可以了，我都是同意的。”这是本技能的持续执行偏好；除非用户后来修改，不再询问“是否继续”“是否上传”“是否发布”“是否同意条款”，不弹选择题、不等待例行审批。

- 用户要求发布后，直接完成素材检查、文案适配、上传、普通上传条款与社区规范的必要勾选、提交和结果核验。常规选择按下文默认值处理，并记录实际决定；进度说明不变成确认关卡。
- 此偏好适用于后续发布任务。在新任务清单的 `authorization` 中记录当前发布请求、实际平台范围和本段持续授权来源；需要时据此设置 `terms_accepted: true` 或传入 `--terms-accepted`，不要伪称用户逐次阅读或新回复了条款。
- 素材性质属于事实，不把“默认同意”当作所有未来视频都原创、无商业合作或适合某类受众的证明。先从当前素材、任务上下文及已确认信息填写，无法确定且必填时记录具体缺项，继续其他可完成步骤。
- 遇到登录、扫码、验证码、工具权限或无法消除的素材/账号歧义，说明实际阻塞及所需操作，不反复发问，不伪造答案或绕过限制。只暂停依赖该条件的步骤，继续其他平台。
- 此偏好不扩大当前任务：仅写文案或修改技能时不发布视频；不自动付费推广、删除旧作品或重复投稿。用户本次明确指定的范围、排除项、草稿与定时要求优先。

## 范围与默认行为

- “全部平台”指上述六个平台；点名的平台列表及排除项优先。支持六个平台不代表每次都发六个平台。恢复任务沿用原清单；新发布任务未指定平台时默认上述全部平台，记录范围后直接执行。
- “微信视频号”“视频号”“WeChat Channels”统一记为 `wechat_channels`；在本技能的视频发布语境中仅说“微信”时默认视频号，并在清单中说明，不另发公众号、朋友圈或私聊。
- 区分 `prepare`（仅本地准备）、`draft`（上传保存平台草稿）、`publish`（立即发布）、`schedule`（平台定时发布）。普通“帮我发布”按立即公开发布理解，在清单中明示；用户指定的可见性优先。
- “创建 skill”“写文案”“检查能否发布”不授权上传。明确要求发布则已授权相关上传和提交，不再逐个平台重复请求确认。
- 同一任务已有的素材、账号、文案、可见性和时间选择持续有效。缺省常规选项直接决定；确实缺少无法推断的信息时按上面的阻塞规则处理。
- 默认仅适配标题、简介和标签，保留视频及原语言。TikTok、YouTube 不自动改成英语。用户指定原文时逐字保留；超出页面限制时保留原意做最小必要缩写，记录实际文案并继续。
- 裁切视频、重配音、换音乐、生成封面、去水印不包含在发布授权中。需要改变素材时说明方案；可以使用平台现有默认封面并记录选择。

## 工具与入口

### B站：使用现有投稿脚本

对原创、无商业合作的 AI 视频立即公开投稿，先读 [references/bilibili-script.md](references/bilibili-script.md)，通过 `scripts/bilibili.mjs` 完成上传、填表、提交和回执读取。这是默认执行路径，不能只阅读脚本后改用浏览器工具逐步点击投稿。

- 先准备清单和脚本运行环境。默认复用已登录的 `main` 持久化配置，直接运行投稿命令，不要每次要求重新登录；只有登录失效时运行 `login`。用户提供已启用的本机 CDP 入口时，用脚本的 `--cdp-url` 复用现有浏览器。未启用入口的日常 Chrome 已登录不代表脚本能直接连接；不导出或记忆 token。
- 参数和授权完整后实际运行 `publish`；已上传未提交的表单用 `resume` 恢复。`check`、`inspect`、文件检查和打开网页均不算执行上传发布。
- 脚本直接定位 DOM；正常投稿不使用截图识别、OCR、多模态坐标点击，也不以逐步读取界面控件并点击的方式替代脚本。为理解视频内容查看抽帧，与操作投稿页面是两件事。
- 遇到依赖、登录或选择器问题，先说明具体错误并按脚本说明处理；不能在尚未尝试脚本时假定它不可用。选择器校准可读取 DOM，修正后仍由脚本执行投稿；上传已开始时遵守恢复规则。
- 只有用户明确指定浏览器投稿，或脚本确实不支持所需投稿类型时，才采用下述通用平台流程，并先说明切换原因。不要默默回退。
- 汇报执行方式时明确是否实际运行了 `bilibili.mjs publish` 或 `resume`，不要把浏览器工具调用或本地素材检查称为“已用投稿脚本发布”。“已选择文件”不等于“上传中”；上传进度和完成状态必须以网页证据为准。

### YouTube：使用投稿脚本

对原创、无商业合作视频立即公开发布，先读 [references/youtube-script.md](references/youtube-script.md)，通过 `scripts/youtube.mjs` 完成上传、填写信息与声明、检查、公开提交和按视频 ID 核验。默认直接读取本机 `~/.local/share/video-publish/youtube/current.json`；本次配置包含原视频路径、Martin 频道和已发布 ID，保留成功状态。

- 优先用 `--cdp-url` 连接已启用调试入口的现有浏览器；只有明确选择 `--profile main` 才开启独立持久化浏览器。普通 Chrome 未提供入口时不假装能够直接复用，也不导出 token。当前日常 Chrome 的登录不等于新建的 YouTube profile 已登录。
- 参数和授权沿用同一清单；普通上传条款按持续授权直接处理。新视频建立新清单，记录持续授权来源，不复制旧视频的素材声明、作品 ID 或成功结果。
- 正常路径运行脚本，不改用逐步 CUA 点击。`check` 和 `inspect` 不算上传，文件选择或视频 ID 不算上传完成。脚本按页面证据报告进度。
- 版权检查明确无当前影响时记录提示后继续；限制未明确或检查未完成则停止提交。发布后必须按 ID 核对频道、标题、源文件名和 Public 状态。
- `resume` 仅恢复 CDP 中仍打开的同一上传向导。关闭的草稿、定时、商业合作和自定义封面尚不支持，使用通用流程前说明原因。
- 已通过隔离网页测试；此前这条视频实际由浏览器工具发布，不能说新脚本已经完成真实投稿验证。不要为测试重发已发布视频。

### TikTok：使用投稿脚本

先读 [references/tiktok-script.md](references/tiktok-script.md)，通过 `scripts/tiktok.mjs` 处理上传、中文文案、AI 声明、立即公开和状态核验。默认读取本机 `~/.local/share/video-publish/tiktok/current.json`。

- 优先连接已启用的本机 `--cdp-url`；只有明确选择 `--profile main` 才开启独立持久化配置，不复制日常浏览器凭据。
- 权限必须是“所有人”。提交前设置并核验；作品行显示“仅自己”时即使审核中也不能记为公开成功。已有作品可用 `set-public` 按 ID 修改权限，刷新后验证。
- 中文输入必须同时匹配编辑器文本和平台字符计数；仅无障碍树文本变化不能证明保存成功。AI 与商业声明开关必须有可读取的真实状态。
- `publish` 新建，`resume` 只恢复仍打开的同一已上传表单；已知作品 ID 只核验或编辑原作品，不再次上传。`submitting/unknown` 不自动重试提交。
- 脚本通过隔离网页测试，尚未完成真实 TikTok 端到端验证。实际页面缺少可访问状态或结果容器时先 `inspect` 校准 DOM；不能默默改用坐标，也不能宣称发布成功。

### 抖音：复用已登录浏览器发布

先读 [references/douyin-browser.md](references/douyin-browser.md)，按已实测的浏览器路径完成上传、填写、AI 声明、公开提交与作品详情核验。抖音尚无 `douyin.mjs`；此路径已于 2026-09-16 完成真实发布，不应描述为脚本发布。

- 用户指定使用已打开的浏览器时，优先复用现有创作者中心标签页及登录会话。浏览器工具能连接时直接执行，不以其他连接方式失败为由反复要求用户启用或重新登录。
- 上传完成后核对标题、描述、话题、封面、自主声明、公开与立即发布。沿用同一任务已确认的内容事实和授权，不重复提问。
- 提交一次后进入作品管理；列表未更新时刷新核验，再打开对应作品详情记录作品 ID 和管理页链接。跳转成功、快速检测通过均不能单独证明已发布。

### 微信视频号：使用投稿脚本

先读 [references/wechat-channels-script.md](references/wechat-channels-script.md)，通过 `scripts/wechat-channels.mjs` 完成临时文件准备、上传、中文文案、AI 标注、单次发表和核验。默认清单为 `~/.local/share/video-publish/wechat_channels/current.json`。

- 默认通过 Chrome DevTools `autoConnect` 复用已登录 Chrome，与本次真实投稿采用同一连接方式，不要求另开独立 profile；已有本机调试入口也可传 `--cdp-url`。首次浏览器连接授权或登录仍由用户完成。
- 脚本自动复制到系统 `os.tmpdir()`，核对大小和 SHA-256 后上传，不转码。不要把 `/tmp`、仓库路径或微信沙盒路径当成上传工具必然允许的目录；不通过关闭路径限制解决错误。
- 当前支持已确认含 AI 生成内容的视频立即公开发布，默认封面、不显示位置、不关联商品/合集/活动。其他声明、自定义封面、草稿和定时类型使用通用流程前说明原因。
- `publish` 新建投稿；`resume` 仅恢复脚本标记过且仍打开的同一表单；已提交或状态不明只能 `verify`。不清除成功记录或为验证脚本重发旧作品。
- 已在真实账号运行脚本 `verify` 核验本次作品；完整上传与提交流程此前由浏览器工具执行。脚本的素材、上传状态、填表与提交逻辑通过隔离测试，不把核验实测说成新脚本完整端到端投稿实测。

### 百家号：使用投稿脚本

“百家号”“百度百家号”统一记为 `baijiahao`。先读 [references/baijiahao-script.md](references/baijiahao-script.md)，通过 `scripts/baijiahao.mjs` 完成已确认含 AI 内容的视频立即投稿；支持系统临时目录副本、账号 ID 核验、作品描述替换、AI 声明、验证码等待、恢复与作品管理核验。

- 正常路径运行脚本，不逐步用浏览器工具代替；`check`、`stage`、`inspect` 不算上传，`verify` 不会新建作品。默认清单 `~/.local/share/video-publish/baijiahao/current.json` 已保存本次作品 ID，重新 `publish` 不会重传。
- 网站选择文件使用 `os.tmpdir()` 下的已校验副本，不使用微信沙盒路径、仓库路径或字面 `/tmp`；上传完成后清理脚本创建的副本。
- 百度滑块/扫码验证由用户手动完成，脚本仅等待回执。已点击发布后，`resume` 只等待或核验，不再点击发布；原上传表单身份缺失时停止，不猜测素材。
- 2026-09-16 浏览器流程已取得审核中回执。新脚本通过隔离测试；本机 autoConnect 未连接成功，尚未实测脚本端到端投稿，不为验证脚本重复投稿。

### 其他平台及脚本不支持的投稿类型

以下连接器/浏览器流程用于脚本尚不支持的投稿类型，不覆盖上面的 B站、YouTube、TikTok、微信视频号与百家号脚本路径。微信视频号的平台字段见 [平台适配说明](references/platforms.md#微信视频号--wechat_channels)。抖音优先按上面的已实测浏览器路径执行。

1. 发现当前可调用、已授权且支持目标平台视频上传的连接器/API。不要凭插件名称假定支持发布，不假造接口或参数。
2. 没有合适连接器时，用可用浏览器工具操作官方后台。尊重指定浏览器，先从工具文档确认页面读取、登录会话和本地文件上传能力。按当前页面操作，不硬编码坐标或旧版选择器。
3. 读取 [references/platforms.md](references/platforms.md) 中本次平台的说明。入口是导航起点；大小、时长、字数、定时窗口及账号功能以当前页面或官方文档为准。
4. 登录、扫码、验证码和二次验证由用户在平台内完成。不索要密码、Cookie、令牌或验证码正文，不导出凭据。单个平台受阻时继续其他已授权平台。
5. 工具无法上传或控制已登录页面时，完成本地发布包，明确尚未上传及用户需要完成的步骤，不能把生成文案报告成发布成功。

## 执行流程

### 1. 素材和参数

- 使用用户附件或明确路径。多个候选文件先按用户明确路径和上下文定位；仍无法唯一确定时记录阻塞，不用“最新文件”猜测；目录批量发布先列出实际文件。
- 检查文件可读、非空，计算 SHA-256。有 `ffprobe` 时读取时长、宽高、音视频编码和大小；没有时标记未检查，利用上传页面校验，不编造检测结果。
- 根据用户描述及可读取的视频内容写准确文案，不凭文件名杜撰剧情。信息有限时使用基于可见内容的简洁描述，不编造剧情。
- 整理目标平台、账号、视频/封面、标题、简介、标签、可见性、立即/定时发布。用户覆盖设置分平台应用。
- 定时记录完整日期、时间和时区，转换到平台页面时区后核对。相对时间解析成绝对时间；优先使用已知用户时区，否则使用当前环境时区并记录；无法确定时区则暂停定时提交并说明缺项。
- 原创/转载、儿童受众、AI 合成和商业合作等必填声明依据已知内容事实填写；不能确定且平台必填时记录缺项，不一律默认“否”，也不重复询问已确认的事实。

### 2. 可恢复清单

用 [assets/publish-manifest.json](assets/publish-manifest.json) 建立本次清单，不修改模板。默认将运行记录保存到系统临时目录的独立 `video-publisher/<唯一任务ID>/` 中，提供实际绝对路径；用户指定保存位置时遵从。临时目录不是永久存储，不承诺长期保留。

- 发布清单、运行日志、抽帧、页面证据及上传暂存副本统一放在系统临时目录的本次任务子目录中（使用 `tempfile.gettempdir()` / `os.tmpdir()` 获取根目录，使用唯一任务目录避免覆盖；macOS 不要硬编码 `/tmp`，当前工具接受的临时根目录可能是 `/var/folders/.../T/`）。不要在项目仓库内创建 `.video-publish-staging`、视频副本或其他运行产物；不以修改 `.gitignore` 代替临时目录。现有脚本持久化账号配置按各脚本文档管理。
- 网站选择文件遇到路径不在允许目录的拒绝时，将用户指定原文件复制到运行时返回的真实系统临时目录，再用该路径选择文件；不要用仓库目录或硬编码的 `/tmp` 代替。工具需要暂存副本时，只复制到该临时目录，保持原文件名及字节内容，并核对副本与源文件的 SHA-256 一致；清单保留原始 `video.path`，另记 `video.upload_path`。不移动、覆盖或转码原文件。
- 使用真实系统临时目录后仍被上传工具拒绝时，记录权限阻塞，不把副本搬进仓库或修改工具安全配置。完成上传后可清理本次创建的大型暂存副本，保留清单供恢复；不要清理其他任务的临时目录。

- 一份清单对应一个视频；批量视频使用多份清单。将 `target_template` 复制到 `targets`，每条对应一个目标平台和账号，填好后移除 `target_template`。
- `targets` 只含本次选择的平台。同一平台多账号须逐一明确，不因登录多个账号就全部发布。
- `target_template.platform` 使用上述平台标识，视频号填写 `wechat_channels`，百家号填写 `baijiahao`。共用现有清单字段，平台专属字段及声明放入 `platform_fields`，具体映射见平台适配说明。恢复旧清单时保留原有目标，不因新增渠道自动补发视频号或百家号。
- 首次上传前核对当前可见账号与指定账号。只有一个登录账号且用户未指定时列入清单后继续；多个账号优先用本任务已指定账号，其次唯一的当前活动账号；仍无法确定时记录该平台阻塞。
- SHA-256 + 平台 + 稳定账号标识用于排查重复。恢复任务先读取上次清单；账号不明时不能沿用另一账号的成功记录。
- 用户明确要求不检查重复上传时，跳过额外浏览历史稿件、搜索同名视频和比较历史素材的步骤。脚本自带的本地状态检查仍由脚本执行；若它阻止执行，如实说明，不把“跳过检查”当成清除记录或重复提交的授权。
- 保存实际填写的文案、设置，每个平台操作后及时更新清单。清单不存凭据、带令牌的上传 URL 或敏感浏览器数据，不自动提交到 Git。
- 提交前展示简洁清单；已获发布授权且信息完整时直接执行，展示不是额外审批步骤。

### 3. 逐个平台上传和提交

1. 按“工具与入口”选择执行路径。B站、YouTube、TikTok、微信视频号与百家号支持的投稿由脚本核对账号并操作上传入口；其他情况打开官方入口，核对账号及当前上传限制。已有投稿的检查遵循用户选择和恢复规则。
2. 上传视频，等页面明确完成上传和必要处理，再填写字段及封面。
3. 复核标题、账号、可见性、时间和必填声明。付费推广、关联商品、自动分享到其他平台等不随普通投稿自动开启。
4. `prepare` 全程只在本地准备。`draft` 仅执行平台明确的草稿/私密保存；无法保存时交付本地发布包，不用公开发布替代草稿。
5. 最终提交前将状态持久化为 `submitting`，随后只提交一次。API 有文档明确的幂等参数时使用；浏览器点击不假定有幂等保护。
6. 从回执、作品管理或详情确认结果，记录作品 ID、真实链接和核验时间。区分上传完成、审核中、已排期和已公开。

### 4. 异常与恢复

- 上传失败且确认没有生成稿件时可重试一次；再次失败记录原因，继续其他平台。
- 提交后超时、页面关闭或响应不明：标记 `unknown`，先去作品管理核对账号、标题、时间、时长和预览；有作品 ID 时优先按 ID 查找。仅标题相同不足以证明同一稿件，未排除成功前不得重传或再次发布。
- 恢复时跳过 `published`、`scheduled`、`reviewing`；`submitting` 按 `unknown` 核查。草稿和已上传记录优先恢复原稿，不重复新建。
- 审核中如实报告；页面明确公开且作品可访问时才记 `published`。不承诺各平台同秒上线。
- 平台不支持目标时间或可见性时说明阻塞和可行选项，不擅自立即公开；只有用户要求后续检查时才创建后续任务或提醒。
- 一个平台失败不撤回其他平台成功作品。删除、撤回或重发已有作品按用户另行指示处理。
