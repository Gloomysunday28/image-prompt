# 抖音浏览器发布路径

2026-09-16 已使用现有 Chrome 登录会话完成真实投稿：45 秒、3840×2160 的 HEVC/AAC 原视频上传成功，作品管理显示“已发布”，详情显示“作品状态正常”。这证明浏览器路径可用，不代表已有独立投稿脚本。控件、页面 ID 和账号每次重新读取，不复用历史 UID 或坐标。

## 1. 复用浏览器和上传表单

- 官方入口：https://creator.douyin.com/ 。从“作品发布”进入视频发布；已打开同一视频的上传页时继续原表单。
- 本次成功使用 Chrome DevTools 浏览器工具：列出页面、读取页面、选择本地文件、填写和点击，再读取结果。已有浏览器工具能连接时直接复用；Playwright CDP 连接超时不代表所有浏览器工具均不可用，不反复重试失败入口。
- 上传前记录页面可见的目标账号，按主技能要求核验用户指定源文件的路径、大小、时长、分辨率和 SHA-256。新任务不能沿用旧账号或旧视频路径。
- 通过当前上传控件选择源视频。若上传工具限制可读目录，只使用工具明确支持的目录；本次 Chrome DevTools 支持系统临时目录，可在 `os.tmpdir()` 下创建任务独立目录，复制原文件并比对 SHA-256 后上传副本。记录暂存路径，不改原文件，不硬编码本次机器的临时路径，不修改工具的目录限制。
- 文件选择工具返回成功只代表选入文件。等待页面上传进度完成、视频预览可用，并核对时长和上传状态；上传中不刷新、不再次选入视频。

## 2. 填写并复核

- 上传后的表单路径为 `/creator-micro/content/post/video`；通过现有页面进入，不凭路径假定已创建稿件。
- 标题栏本次占位文字为“填写作品标题，为作品获得更多流量”；描述是独立富文本区域。分别填写标题与描述，逐项读回并核对字符计数及右侧预览，避免填充工具追加到旧文字。话题通过“#添加话题”或当前编辑器添加，核对最终文案及实际话题状态。
- 已确认是 AI 内容时，在“自主声明”选择“内容由AI生成”，核对预览中的“作者声明：内容由AI生成”。原创、商业合作等事实沿用同一任务的确认结果；不要把 AI 开关视为其他声明也已填写。
- 封面优先使用用户提供素材或平台默认封面。已有封面素材时，在“设置封面”中选择横封面，使用“上传封面”，确认预览后点击“完成”；竖封面为可选项时可按当前任务选择设置或“暂不设置”。不自动点击“AI生成封面”，不因有发布授权就擅自制作衍生素材。
- 立即公开任务核对“谁可以看”为“公开”、“发布时间”为“立即发布”。不填写无关地理位置、关联热点、商品或推广。
- “快速检测”的“作品未见异常”是提交前检查结果，不是发布回执。

## 3. 提交一次并核验

1. 将实际文案、声明、可见性和封面选择写入清单；提交前持久化 `submitting`，再点击一次“发布”。
2. 本次提交后跳转到 `/creator-micro/content/manage?enter_from=publish`。跳转只证明流程推进，仍需找到对应作品；列表初次可能显示旧数据，等待加载完成后可刷新作品管理页。
3. 按账号、标题与描述、发布时间、时长和预览定位作品。“已发布”与“审核中”分别记录；不要把其他历史视频的状态当成本次结果。
4. 点击对应作品标题打开详情。本次详情路径为 `/creator-micro/work-management/work-detail/<作品ID>?enter_from=content`，可从实际地址记录 `post_id`、`management_url`，核对“作品状态正常”和正确文案、时长、时间。
5. 公开设置与发布结果核验完成、作品可访问后记 `published`；只能确认收到投稿时保留 `reviewing` 或 `unknown`。公开链接只记录实际页面或分享入口提供的地址，没有取得时交付标注清楚的管理页链接。

## 恢复要点

- 页面交互报超时后先重新读取状态；本次部分操作虽报错但页面已推进，不能盲目重复点击。
- 浮层或“审核通知”加载不出时读取当前页面定位遮挡，按实际关闭按钮处理；不据此判断投稿失败。
- 已上传的表单继续填写，已提交的作品去管理页核验。已取得作品 ID 后只核验或编辑原作品，不重传、不重复发布。
- 登录失效、扫码或二次验证由用户在平台内处理；其他日常选项按既有授权继续。
